# AIEOP — AI Engineering Copilot for GitHub

An AI layer over a real GitHub repository: ask questions in natural
language, get evidence-backed answers generated by Claude and grounded
strictly in your repo's actual commits, PRs, issues, CI runs, and docs -
not fabricated, not templated.

## Why GitHub-only

Early versions of this tried to integrate GitHub + Taiga + Discord +
simulated monitoring simultaneously. That made for an impressive
architecture diagram and a useless product: almost nobody has a Taiga
account or a Discord bot lying around, so every demo required fake seeded
data. GitHub is the one integration anyone with a repo can connect in
under a minute with a single token. Everything now runs on real data from
a real repo, or the built-in demo scenario - never a mix that only looks
real.

## Why the AI is now real

Earlier, the "AI" in two of the most visible places was a stand-in: the
knowledge-base answer was just the best-matching paragraph returned
verbatim, and intent routing was regex. That's honest engineering
sequencing (build the deterministic pipeline first, wire the model in
once the plumbing is proven) but it isn't a usable product. Claude is now
wired into the two places that most needed real reasoning:

- **Knowledge base answers** - grounded strictly in retrieved document
  excerpts, with an explicit instruction never to use outside knowledge
- **Incident root-cause explanations** - phrases the exact facts,
  hypotheses, confidence, and recommendation the deterministic Incident
  Agent already computed; it narrates evidence, it doesn't invent it

Both fall back cleanly to their previous deterministic behavior if no
`ANTHROPIC_API_KEY` is set - the platform never breaks over a missing key,
it's just less fluent without one.

## How to actually use it

1. Get a GitHub personal access token (`repo` scope is enough to start)
   and an Anthropic API key (optional but recommended).
2. `cp backend/.env.example backend/.env` and fill in `GITHUB_TOKEN` and
   `ANTHROPIC_API_KEY`.
3. `docker compose up --build`, open the dashboard.
4. In the top bar, click **"Sync GitHub repo"** and enter `owner/repo`
   for any repository your token can read. This pulls real commits, PRs,
   issues (with GitHub milestones mapped to sprints), CI run history, and
   the README - into every panel.
5. Ask the Chat panel real questions about that repo: *"what changed
   recently"*, *"summarize the open issues"*. Check Overview for a real
   computed health score. Check Knowledge Base for grounded Q&A over the
   README.

No GitHub account handy? Click **"Load demo data"** instead for a fully
seeded, self-contained scenario (a live investigated incident, a sprint
in progress, a dependency chain) - see `backend/app/demo/seed.py`.

## What's implemented and tested

**Foundation**
- Real auth (FR-001) — password + JWT via `POST /api/auth/register|login`,
  `GET /api/auth/me`. Dashboard still uses a role dropdown for convenience
  in dev; a real deployment (`ENVIRONMENT=production`) requires a token.
- **RBAC** (FR-021/040) — an agent's effective permission set is always the
  intersection of its own allow-list, an "AI agent ceiling," and the
  acting user's own role.
- **Unified data model** (FR-005), managed by Alembic migrations.
- **GitHub adapter** — repos, commits, PRs, issues (milestone → sprint),
  CI workflow runs, README, and write actions (create issue, create
  branch, trigger CI). Degrades to "not configured" rather than
  fabricating data when no token is set.
- **GitHub repo sync** (`app/integrations/github_sync.py`) — pulls all of
  the above into the unified data model for a given project. Idempotent:
  safe to re-run, upserts rather than duplicating.

**AI & reasoning**
- Coordinator + Project/Developer/Incident agents, root-cause analysis
  with fact-vs-hypothesis evidence, conversation memory.
- RAG knowledge base — real chunking, real vector retrieval (a
  dependency-free hashing embedding), and now real Claude-generated
  answers grounded in the retrieved excerpts.
- Incident root-cause narration — Claude phrases the deterministic
  Incident Agent's evidence into a fluent explanation, never introducing
  facts beyond what was given.

**Intelligence**
- Risk detection (project/code/deployment/incident), Project Health
  Score, a small explainable predictive sprint-risk model, timeline
  reconstruction, dependency awareness (BFS over `Service.depends_on`),
  and technical debt detection.

**Autonomous actions**
- Event-driven proactive detection — can auto-create an incident with no
  user interaction, reusing the Incident Agent's own correlation logic.
- Risk-based approval workflow — low-risk actions auto-execute,
  medium/high-risk actions queue for human approval, every outcome is
  audited.

**Dashboard** — Overview (health score + risks), Chat, Incidents
(list → timeline → dependency impact → tech debt), Knowledge Base
(ingest + grounded query), Approval Center, Integration health. A
project switcher in the top bar handles picking a project, syncing a
real GitHub repo, or seeding the demo scenario.

**84/84 backend tests pass** (`pytest`). Frontend builds cleanly.

## What's still not built

- Global engineering search (FR-035) and full report generation (FR-029).
- Notification preferences UI (FR-028).
- A real login screen (JWT auth works and is tested; dashboard still uses
  a role dropdown for convenience).
- Deployment to a real host.
- Real build-failure log investigation (currently: build pass/fail status
  syncs from GitHub Actions, but job-level log parsing isn't wired up -
  documented next step for a GitHub-only "why did CI fail" flow).

## Running it

### Docker Compose (Postgres + Redis + backend + frontend)

```bash
cp backend/.env.example backend/.env   # fill in GITHUB_TOKEN and ANTHROPIC_API_KEY
docker compose up --build
```

Backend: http://localhost:8000 (docs at `/docs`). Frontend: http://localhost:5173.

### Backend locally without Docker (SQLite)

```bash
cd backend
pip install -r requirements.txt --break-system-packages
uvicorn app.main:app --reload
```

### Frontend locally

```bash
cd frontend
npm install
npm run dev
```

### Tests

```bash
cd backend
pytest -v
```

### Database migrations (Alembic)

`app.main`'s startup hook calls `Base.metadata.create_all()` as a
fresh-DB convenience only - it never alters existing tables. Alembic is
the actual source of truth for schema changes:

```bash
cd backend
alembic revision --autogenerate -m "describe your change"
alembic upgrade head
```
